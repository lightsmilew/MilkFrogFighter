# 奶蛙街头 · MILKFROG FIGHT CLUB

经典奶蛙表情包的横版街机格斗小游戏。奶油色小报页面、午后老街擂台、平视对手的圆眼奶蛙。纯 HTML / CSS / JavaScript / Canvas，运行时没有框架、CDN 或后端依赖，可以部署在 GitHub Pages 的仓库子路径。

## 立即运行

安装 Node.js 20 或更新版本后，在项目目录运行：

```sh
npm run dev
```

打开 `http://localhost:4173`。无需 `npm install`。页面使用 ES modules，请通过本地 HTTP 服务打开。

## 已实现

- 人机对战：三档难度，三局两胜，每局 90 秒。
- 同屏双人：两套键盘按键，也支持两只标准手柄。
- 自由练习：无限奶气、无限时间、连招后自动回血，可切换格挡木桩。
- 六位选手：奶蛙（螺旋丸 / 反击架势）、奶绿（分身 / 穿身风刃）、奶红（霸体 / 延迟火柱）、奶紫（换边幻步 / 牵引结界）、奶粉（回旋心弹 / 三层绯印）、奶蓝（三层霜印 / 挡弹冰镜）。
- 投币后同页选择玩法、脾气与街区，设置界面仍占用原来的游戏窗口；难度仅人机模式显示。首页保留六角色展示（投币后可选）、操作速查、完整招式入口和原页脚。两张地图：晴日老街、雨巷街口。雨天地面有湿润反光，叠加实时雨滴与涟漪；主页保留选蛙区和操作速查。
- 六套独立流派，每套 28 个招式槽：螺旋近战、风影分身、熔火霸体、幻月牵引、绯绫印记、冰镜封锁。普攻节奏、拳脚分支、战术技能与组合必杀均按角色解析。每位角色一张 48 帧图集，包含八帧行走、六帧专属跑步，替换三张旧移动图；旧动作按新图的肤色、高光和阴影重新配色。详见 [战斗设计](docs/COMBAT.md)。
- 短施法、长控制：施法者先恢复，能接近被控对手；同次施法不能无限刷新控制，闪移可脱控。后 + 必杀中奶红追爆留下余火、奶粉双心丝带追踪折返、奶蓝立镜交叉夹击再冻结中心；奶蛙后 + 必杀为居中螺旋回流，空中奥义为真实大玉抛物线坠击；奶绿后 + 必杀为双侧分身交叉突袭，空中奥义为分身俯冲与交叉风刃，预警、轨迹和碰撞同步。其余角色保留各自的瞄准压制与延迟爆发。
- 战斗角色缩至此前的 70%，站立高度约占战场高度 20%；双击方向冲刺、持续 2.15 倍奔跑、高 / 中 / 低 / 空中压制 / 对空 / 投技判定、站防与蹲防、命中取消、气功相消、打击停顿与击退。
- 3840 单位宽的街区、向上延伸的活动空间与多层棚架 / 屋檐 / 露台，显示窗口保持 1280×720。共享镜头跟随双方并按高度差缩放，HUD 固定，头顶箭头标识玩家 / 电脑 / 木桩。
- 按住跳跃可落地连续跳，空中松开再按可二段跳，两次起跳使用相同初速，六位角色均可从地面跳到第一层或二段跳到第二层；下降时可停在平台，按住下穿过平台。闪移可穿人、躲攻击、打断短暂受击状态，最多储存 2 次，每 3 秒恢复一次，使用第二次不会重置已有恢复计时。
- 轻击、重踢、绊倒、浮空、冰冻与倒地有不同表现；抱摔经过抓取、越肩抛掷、另一侧落地和起身。倒地恢复带保护，避免一直被压在角落。
- 伤害整体缩至此前 44%，长连段衰减更强；电脑按命中确认接连招，并判断收招反击、对空、投技、远程拦截与闪移脱身；三档难度使用不同反应和执行概率。对固定乱按脚本，简单 / 普通 / 困难电脑分别赢 18 局中的 0 / 6 / 18 局，这不代表真人胜率。
- 动态光效：挥拳拖光、踢腿弧光、命中星芒、冲击环、技能尾焰、地面震波、蓄力光晕及必杀闪光。
- 声音：打击、格挡、起跳、落地、技能、必杀及原创街机背景乐；大笑使用随项目保存的**网络经典录音**，没有用合成笑声替代。
- 手机虚拟摇杆：拖动移动、推满奔跑、同向连拨冲刺、上推跳跃、下拉蹲下；拳、脚、技、必杀四个攻击键，加闪移和防御键，共六键支持多指操作，方向 + 必杀可以选择组合大招。横屏使用紧凑擂台布局。
- 主页与选择界面的右上角均可切换全屏，投币进入选择界面保留全屏状态。对局退出全屏后自动暂停，点击继续才恢复。普通模式下暂停与全屏位于战斗顶部工具栏；全屏收起整行工具栏，保留两个悬浮控制钮，画面铺满屏幕并扩展实际视野。暂停和结算框均适应矮屏，两种状态下隐藏触屏操作。体力与奶气条上下对齐，数值居中，配色分别为暖金 / 低血红和青绿。

- 启动只优先下载开局角色的合并图集；地图预览、主页装饰与选中地图随后加载，二维码模块仅打开分享时加载。发布时脚本合并压缩为一次请求，资源按内容生成文件名，浏览器保留使用过的资源；重新部署只重新下载变化的文件。当前限速首开约 4.37 秒（1.6 Mbps / 120 ms 延迟 / 4 倍 CPU），见 [性能记录](docs/PERFORMANCE.md)。
- 分享面板提供系统链接分享、复制链接、二维码邀请图片的系统分享与保存；未开放系统分享的浏览器仍可使用链接与图片。二维码直接在本机生成，无第三方接口。

P2 兼容数字小键盘，也支持 `N / M / , / .` 对应拳 / 脚 / 技 / 必杀。标准手柄用摇杆 / 方向键移动，上推跳跃，A/B/X/Y 出招，肩键防御，上 / 下 + A 为升龙 / 抱摔，按下左摇杆闪移。手机摇杆持续上推会落地连跳，松开再上推触发二段跳；右侧“闪”使用双段进度与单个恢复倒计时。Enter 在对战中用于 P2 防御，在首页 / 暂停 / 结果界面继续用来开始 / 继续。

iPhone 的 Safari 不提供任意网页元素的原生全屏（`requestFullscreen` 仅 iPad 可用），因此全屏按钮优先尝试标准 / WebKit API：接口缺失、被拒绝或请求悬挂时，立即改用可见窗口内的沉浸模式。沉浸模式按 `visualViewport` 定尺寸，并在旋转、地址栏伸缩后多次补测；地图铺到屏幕四边，HUD 与操作键另留刘海和手势安全区。想隐藏地址栏，可在 Safari 将页面「添加到主屏幕」并作为 Web App 打开；开打后自动铺满视口。仓库已提供 `manifest.webmanifest`（`standalone`、主题色）和 180 / 192 / 512 图标。普通标签页无法强制隐藏浏览器地址栏。实现与测试范围见 [兼容性说明](docs/COMPATIBILITY.md)。

声音：iPhone 只允许在用户手势内启动 Web Audio，所以第一次点按（包括“投币开打”）就会当场创建并恢复 `AudioContext`，切后台、暂停回来或上下文被挂起时会在下一次点按重试；设置面板在 iOS 上会提示侧边静音开关可能让网页合成音无声。详见 [兼容性说明](docs/COMPATIBILITY.md)。

## GitHub Pages 部署

### 使用自带 GitHub Actions（推荐）

1. 将此项目的源文件提交到 GitHub 仓库的 `main` 或 `master` 分支，包括 `.github/workflows/pages.yml`、`package-lock.json` 与 `assets/`。
2. 打开仓库 **Settings → Pages → Build and deployment → Source**，选择 **GitHub Actions**。
3. 推送代码或手动运行 **Test and deploy the arcade**。流程会运行 `npm ci`、战斗测试和生产构建，然后发布 `dist/`。
4. 在部署任务的 `github-pages` 环境中打开站点链接。

配置依据：[GitHub 官方 Pages 发布说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。所有游戏资源使用相对路径，兼容 `https://用户名.github.io/仓库名/`。

### 手动上传静态成品

```sh
npm ci
npm run build
```

把 `dist/` **里面的内容**上传到发布分支根目录，并在 Pages 中选择 **Deploy from a branch → 对应分支 → /(root)**。也可解压交付的 `releases/milkfrog-pages.zip` 后上传。上传已构建的成品无需安装依赖或 API Key。直接发布源码根目录会绕过脚本合并和缓存优化。

源文件、Pages 工作流和可部署静态包已经准备好。本轮修改未推送到远程仓库。

131 项测试覆盖基础战斗、1000 血量的伤害 / 削血 / 回血换算、冲刺、两次闪移及 3 秒逐次恢复、连续跳与二段跳、六位角色在两张地图的实际平台可达性、宽地图镜头、高低段判定、抱摔全过程、起身保护、角色效果、连招和多段必杀。新增控制脱身、不同远程 / 空中奥义、余火跳避、双绫返程、镜面挡弹、独立走跑动画、合并图集无冗余文件与相邻矩形重叠、顶墙相位停止及二维码独立解码检查。

`npm run test:fullscreen` 检查主页 / 选择界面右上角按钮、全屏下配置并开打、原生与沉浸模式退出暂停和返回大厅。

`npm run test:lobby` 检查投币、同窗同页配置、角色锁定 / 开放及原页脚保留；`npm run test:spiral-wind` 检查四个重做奥义的实际命中与渲染。

可选浏览器检查 `npm run test:browser` 需要 Playwright。可以设置 `PLAYWRIGHT_MODULE` 为已有的 Playwright ESM 模块 URL，并设置 `BROWSER_EXECUTABLE` 使用已有浏览器；`TEST_URL` 可指向仓库子路径。该检查实际验证键盘双人、暂停 / 恢复、设置保存、经典录音解码、手机摇杆、双指攻击、横屏与全屏，并输出 `artifacts/browser-report.json` 和截图。

`npm run test:viewport` 额外检查六种屏幕比例下的暂停 / 结算、全屏场景四边、半透明摇杆、触摸键间距、双资源条数值和主屏幕自动铺满；设置 `MOBILE_ENGINE=webkit` 可改用 Playwright WebKit 复测。

`npm run test:sky-hud` 检查两张重绘高背景、最高露台的二段跳、SVG 全屏控制钮及暂停 / 恢复图标。场景画面覆盖高度从 1420 扩展为 3840，源码记录见 [背景重绘](docs/stage-prompts.md)。体力上限为 1000、奶气上限为 100；奶气条与血条共用外框，条内只显示数值。

`npm run test:mobile` 针对 iPhone 反馈：在 iPhone Safari 没有 Fullscreen API 的环境里检查沉浸模式尺寸、旋转重铺、竖屏提示、添加到主屏幕说明，以及 `AudioContext` 是否真的在手势内创建并进入 `running`（输出 `artifacts/verify-iphone-*.png`）。

构建后运行 `npm run test:delivery`，检查仓库子路径、清空 HTTP 缓存后的资源复用、模拟新部署、缓存受限回退及加载失败重试。`npm run test:startup` 检查限速首开和生产环境仅一次脚本请求。

`npm run test:tactics-share` 在四种屏幕下检查分享框、真实 PNG 解码、保存图片、两次独立用户手势内调用系统链接 / 图片分享，并检查六套八帧步态和不同远程奥义画面。`MOBILE_ENGINE=webkit` 可切换 WebKit；分享调用在测试中模拟，不会向外部应用发送消息。
