# 游戏架构

## 运行与渲染

游戏是完全静态的 ES modules 应用。`app.js` 用 `requestAnimationFrame` 驱动绘制，累计时间后按 1/60 秒调用 `Game.tick`。单帧最多接纳 0.1 秒，避免切回标签页时补算大量失去交互意义的时间。失焦和页面隐藏会自动暂停。

`Game` 不访问 DOM、Canvas 或 Web Audio，可以在 Node.js 中直接测试。它通过事件通知界面和声音，随机源可注入以进行可重复的 AI 压测。

## 战斗状态

比赛经历 `attract → intro → fight → roundOver → intro / matchOver`。每局重置选手的体力和位置，整场命中数与最佳连击独立累计。超时比较剩余体力；同血量平局不记胜场，继续下一局；先赢两局结束。

角色有移动、奔跑、冲刺、跳跃、蹲下、防御、出招、受击、大笑、倒地与胜利状态。每位角色的 27 个招式槽分启动、有效和收招三段。近战只在有效帧内检测攻击框与圆润轮廓的三段受击框；蹲下切换受击框。单段招式只命中一次，多段招式以独立脉冲编号记录已命中的段数。

确认命中后开放 0.38 秒取消窗口，按招式 rank 接受升级招式，包括 J 三连拳、拳 → 脚 → 技能 → 必杀。输入缓存 0.20 秒，命中停顿期间仍接收按键。三次连续命中后，中立必杀选择六段终式；本连招命中的付费技能最多抵扣 35 奶气，避免技能刚扣费就无法接原本满格的大招。未确认命中的技能不能抵扣。

方向边沿保留 0.6 秒历史，以朝向转换成前 / 后 / 下，识别半秒内的下 → 前指令。同向两次输入间隔小于 0.26 秒触发 0.20 秒冲刺，继续按住保持 2.15 倍奔跑。前冲速度 1180、后冲 1020，摇杆全推和左 Shift 同样可奔跑。跳跃初速 1160–1280，重力 2050，离散物理下最高约 319–389 个世界单位；二段跳使用完整起跳初速，让较早输入也能上第二层。短暂起跳躲避窗口覆盖普通地面攻击，对空与空中压制仍能命中。数值集中在 `config.js`，见 `TUNING.md`。

高段显式避开蹲姿，低段避开离地超过 34 单位的角色，投技不能抓空中。高 / 中段可正面防御，低段需要蹲防，空中压制需要站防，投技破防。几何检测随后排除真实距离之外的命中。地面角色互相挤开，空中可以换边；攻击期间锁定朝向。

技能拥有独立投射物和生命期。双方同级投射物相消，必杀压过普通气功。奶绿使用短距离冲刺刃光，奶红使用贴地冲击，奶紫的泡泡命中后短暂减速。防御只覆盖正面，承受少量削血并积累能量。

## 输入

输入层保存“持续按住”和“刚按下”两组状态。攻击、跳跃消费按下边沿，移动消费持续状态。一个模拟步只消费一次边沿，补帧不会重复起跳或攻击。

摇杆用 Pointer Events 与 pointer capture 跟踪单个手指，径向死区避免漂移，独立阈值支持斜向。水平推满触发 run；持续上推在落地后重复跳跃，空中新的上推边沿消费一次二段跳。键盘持续按住 / 松开再按的规则相同。四个攻击按钮、闪移与防御键独立跟踪指针；抬手、取消、失焦和暂停释放状态。

## 宽地图、平台与镜头

显示窗口固定 1280×720，世界宽度为 3840，顶部扩展至 -700，地面保持 y=610。棚架、屋檐和露台是数据驱动的单向平台。物理比较上一帧与下一帧脚底，下降穿过顶面时落地，向上穿过不阻挡；支持边缘走落和按住下穿过。落地重置一次空中跳跃机会。

共享镜头跟随双方，水平和高度差过大时缩小视野。构图预留固定 HUD 和头顶身份条的屏幕像素安全区，快速二段跳与抱摔不能将头部推出可见范围。平滑跟随受实时可见边界约束。HUD 和底部街区缩略图在屏幕坐标绘制，场景、平台、角色、标识与动态雨滴在世界坐标绘制。

晴日和雨天地形通过 `STAGES` 选择，平台布局略有区别。场景 PNG / WebP 使用 imagegen 生成；雨滴轨迹与地面涟漪由 Canvas 按时间实时绘制，减少动态偏好下减少雨滴并停止运动。

## 受击与节奏

伤害使用原始招式值乘以 0.44，连段每次衰减至 80%，最低 28%；独立回合上限调整为 90 秒。AI 与玩家使用同一套费用、硬直和伤害规则；固定种子对战用于检查节奏，不代表真人难度。

受击记录 flinch / body / trip / launch / tumble / freeze / charm 等反应，渲染使用不同姿态、重心、旋转及特效。绊倒和浮空落地后进入倒地与起身保护。闪移最多储存 2 次，每 3 秒恢复一次，第一次使用开始计时，第二次不会重置进度；两次用尽需要依次恢复。闪移期间支持缓存下一次输入，结束后接续完整位移，拥有短暂无敌与穿人能力，受击 0.1 秒后可脱身，取消对方连段窗口。

抱摔由独立双人动作记录驱动：抓取后锁定双方控制，目标沿越肩弧线移动至另一侧；落地结算一次伤害、冲击效果、倒地与起身。靠墙时调整攻击者位置，保证仍能换边。奶粉技能按攻击编号限制一次回血；奶蓝技能附加短暂冰冻表现与减速。

## 图像和光效

人物保留基础十二姿态与补充八姿态，另有六位角色各四个独立的新动作。离线脚本 `scripts/prepare-assets.py` 提取主要 alpha 连通轮廓、恢复越界拳脚、移除邻格残肢并校准脚底锚点，按新图肤色的五个明暗层次统一旧动作。眼睛、肚皮与手脚排除在肤色映射之外。最终每位角色是 8×3 的 24 帧 WebP，位置和锚点随 `assets/fighters/frames.js` 保存。浏览器不再执行连通分量搜索与逐像素染色。

所有图集按站姿身高统一尺寸：站立 145.6、蹲下 91 世界单位，即此前的 70%。图像、受击框、近战距离、投射物和光效一起缩放，选蛙卡片保持原展示大小。渲染叠加呼吸、步态、受击倾斜、大笑抖动与冲刺残影。离线配色保留浅绿眼睛、奶白肚皮与灰褐手脚。头顶角色标识保留箭头与描边文字，背景透明。

场景使用本地 WebP。出招弧光、蓄力、爆闪、星芒、冲击环、粒子和气功尾焰由 Canvas 即时绘制。粒子总数限制为 240；减少动态效果偏好默认关闭震屏。

## 音频和部署

Web Audio 在用户首次交互后解锁。短打击声由振荡器、噪声和包络实时合成；背景乐是独立音量总线上的原创节拍循环。经典大笑从本地 MP3 解码播放，不用合成声音代替；播放时降低背景乐，暂停会停止样本。异步加载有代际标记，防止退出后迟到的笑声开始播放。

`build.mjs` 只复制运行需要的文件，排除参考图、源 PNG、测试和文档。资源均以相对路径或 `import.meta.url` 解析，GitHub Pages 项目子路径无需改配置。GitHub Actions 先测试再打包，PR 只验证，默认分支才发布。


## 流派与电脑

`styles.js` 将通用输入槽解析为各自的名称、节奏、动作、位移及元素机制。`abilities.js` 管理可格挡的分身、延迟场、牵引、返程弹、冰镜与叠层效果。持久技能共用常规受击、无敌和消失规则。`ai.js` 根据可见攻击与场景位置决定接招、反击、追击和防守，不读取玩家未来输入，不修改伤害、奶气或闪移库存。详细设计与来源见 `COMBAT.md`；资源调度与启动证据见 `PERFORMANCE.md`。


方向 + 拳由 `Game.chooseMove` 统一解析。上 + 拳会取消待起跳缓冲，并抑制同一次方向保持产生的普通连跳；地面单独上推提供 80 ms 合招窗口，纯跳跃的躲避即时生效。下 + 拳选择抱摔，后 + 拳选择蹲掌。连续受击的 `hitstunTime` 独立累计，不因后续击中反复归零，避免堵死闪移。AI 的闪移感知在普通思考计时之前，每个威胁只决策一次；命中接招也只在每次确认时抽样一次。

战斗静止使用图集第 0 帧；第 20 帧的新架势仅用于出招准备和首页选角头像。`share.js` 清理预览参数，提供原生分享、复制和手动复制三种路径；本地地址使用已存在的公开入口，线上部署使用自身目录地址。
